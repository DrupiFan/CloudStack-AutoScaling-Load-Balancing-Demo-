# UGT Cloud — დიზაინის გადატანა არსებულ აპლიკაციაში

## ფაილები

- `ugt-cloud-demo.html` — დამოუკიდებელი HTML/CSS/JS პროტოტიპი. იხსნება პირდაპირ ბრაუზერში, ინსტალაციისა და სერვერის გარეშე. ოფიციალური ლოგო და Inter შრიფტი ჩაშენებულია.
- `ugt-cloud-desktop.png` / `ugt-cloud-mobile.png` — რეალურად დარენდერებული ხედები.
- `ugt-cloud-concept.png` — ImageGen-ით შექმნილი საწყისი ვიზუალური მიმართულება.

ტექსტები დარჩა ინგლისურად, არსებული დემოს შესაბამისად. პროტოტიპის ყველა მაჩვენებელი საილუსტრაციოა. ტრაფიკის გენერატორი ლოკალურად სიმულირებს პროცესს; შეყვანილ URL-ზე მოთხოვნებს არ აგზავნის.

გამოსაცდელად ჩაწერეთ `http://10.10.1.100`, აირჩიეთ preset და დააჭირეთ Start traffic surge. Auto-scaling spike 28 წამში ამატებს მეოთხე სერვერს. Stop-ის შემდეგ 6 წამში დამატებული სერვერი იხსნება. Load balancing preset CPU-ს დაბალ დონეზე ინარჩუნებს.

## ტექსტი AI კოდის მწერლისთვის

გადააკეთე არსებული UGT Cloud Auto Scaling & Load Balancing აპლიკაციის frontend თანდართული `ugt-cloud-demo.html`-ისა და დარენდერებული სქრინების მიხედვით. შეინარჩუნე არსებული backend, ავტორიზაცია, endpoint-ები და ტესტის რეალური ლოგიკა. პროტოტიპის ლოკალური სიმულაცია შეცვალე არსებული API-ის მონაცემებით. არ გადაიტანო sample server-ები ან სიმულირებული scale-out წარმოების აპლიკაციაში.

შეინარჩუნე თეთრი პანელები, ღია ცივი ფონი, ოფიციალური UGT Cloud ლოგო, ლურჯი ძირითადი ღილაკები, ცისფერი/ტურქუაზის დიაგრამა, თხელი საზღვრები და წაკითხვადი ტიპოგრაფია. Desktop-ზე სერვერები ცხრილია; 480px-მდე თითოეული სერვერი ცალკე კომპაქტურ ბლოკად გარდაიქმნება. Traffic generator და Request distribution 780px-მდე ერთ სვეტში გადადის. მეტრიკები გამოითვალოს აქტიური სერვერების რეალური მონაცემებიდან. Health მდგომარეობები მოიცავდეს აქტიურ, newly scaled, გადატვირთულ და removed სერვერებს. Request distribution გამოიყენებდეს `/distribution` პასუხს, მიუხედავად იმისა რომ პროტოტიპში ჯამი sample server-ებიდან ითვლება.

## არსებული endpoint-ების კონტრაქტები

კონტრაქტები წაკითხულია დემოს საჯარო frontend კოდიდან; backend-ის კოდი და ცვლილებები ამ დავალებაში არ შესრულებულა.

| Endpoint | გამოყენება |
|---|---|
| `GET /instances` | მასივი: `name`, `ip`, `status`, `cpu`, `ram`, `request_count`, `first_seen` |
| `GET /distribution` | ობიექტი `{server_name: request_count}` |
| `GET /logs` | მოვლენების მასივი: `ts` Unix წამებში, `type`, `message` |
| `GET /loadtest/status` | `running`, `sent`, `success`, `errors`, `started_at`, `ramp_seconds`, `end_time`, `last_error` |
| `POST /loadtest/start` | JSON: `{target, intensity, duration_seconds}` |
| `POST /loadtest/stop` | გაჩერება; არსებული frontend აგზავნის body-ის გარეშე |

მოქმედ frontend-ში polling ინტერვალია 2000ms. არსებული preset-ებია Load balancing → intensity 1 / duration 60 და Auto-scaling → intensity 4 / duration 120. სლაიდერების დიაპაზონებია intensity 1–4 და duration 30–300, ნაბიჯი 15 წამი.

DOM-ში სასარგებლო კავშირები: `server-rows`, `distribution-legend`, `donut`, `chart-total`, `log-rows`, `traffic-status`, `target`, `intensity`, `duration`, `startBtn`, `stopBtn`, `stat-sent`, `stat-success`, `stat-errors`, `stat-timeleft`. CSS-ის ფერები ცენტრალიზებულია `:root` ცვლადებში.

რეალური მონაცემები ჩასვით უსაფრთხოდ `textContent`-ით ან შესაბამისი framework-ის escaping-ით. API-ის შეცდომა აჩვენეთ ხილულად; მიუწვდომელი backend არ უნდა გამოიყურებოდეს როგორც ჯანმრთელი sample cluster. მონაცემების მოსვლისას აჩვენეთ loading/empty/error მდგომარეობები. დაიცავით არსებული start/stop მოთხოვნების ავტორიზაცია.

## ვიზუალური შემოწმება და მიღებული ცვლილებები

ჩაშენებული ბრაუზერი ვერ გაეშვა Windows sandbox-ის setup-ის შეცდომის გამო. შემოწმება შესრულდა Playwright-ით, დაყენებულ Edge-ში. გამოყენებულია `view_image` როგორც კონცეფციისთვის, ასევე საბოლოო დარენდერებული გვერდისთვის.

შედარებულია ლოგო, ჰედერის განლაგება, სათაურების იერარქია, ღია ფონი/ლურჯი პალიტრა, სერვერების ცხრილის ველები, კონტროლები, დიაგრამა და მოვლენების ჟურნალი. კონცეფციის დაახლოებით 1346×1168 viewport-ი შემოწმდა 1344×1168-ზე. სრულად შენარჩუნებულია ძირითადი სექციების თანმიმდევრობა და კონცეფციის ვიზუალური სისტემა; HTML ბუნებრივად სქროლდება და სურათის სიმაღლეზე ფიქსირებული არ არის.

შესწორდა ზედა დაშორება, ცხრილის რიგების სიმაღლე, ფორმის სიმჭიდროვე და შრიფტის რეალური bold წონა. შეგნებული განსხვავებები: ოფიციალური ლოგოს ზუსტი ფაილი, ბრენდის cobalt ღილაკები, სიმულირებული მონაცემების აღმნიშვნელი ტექსტი, CPU ramp-ის მოკლე განმარტება, დინამიკური რეალური დროის ფორმატი და ჯამიდან სწორად გამოთვლილი პროცენტები (მესამე სერვერი 33.4%). სხვა პირველ ეკრანზე დამატებული სექციები არ არის.

შემოწმებულია baseline მნიშვნელობები, URL-ის ვალიდაცია, ორივე preset, ცარიელი ფილტრი, Start/Stop, კონტროლების გათიშვა მიმდინარე ტესტისას, CPU/მოთხოვნების განახლება, მეოთხე სერვერის დამატება, scale-out ფილტრი, scale-in, ავტომატური დასრულება და გვერდის სიგანე 320/390/768/1024/1344/1440px-ზე. JavaScript console/page შეცდომები: 0. პროტოტიპის ავტომატური გარე HTTP მოთხოვნები: 0.

ეს არის frontend დიზაინის ნიმუში. რეალური backend ინტეგრაცია არ არის განხორციელებული ან დატესტილი. QA შესრულდა Edge Chromium-ზე; Safari/Firefox ცალკე არ შემოწმებულა.
